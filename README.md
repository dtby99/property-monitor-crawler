## 几个我踩过的坑

**坑一：请求没开 JavaScript 渲染。** 链家的房源列表是动态加载的，普通请求只能拿到空壳 HTML。ScraperAPI 有个 `render=true` 参数，打开之后就能拿到完整渲染后的页面。但渲染请求会多扣调用次数（大概按5次计），所以别有请求都开，只在需要的页面开。

**坑二：没做去重逻辑。** 一开始我只对比房源ID，结果同一套房降价了我没收到通知。后来加了价格字段的对比才解决。这不是工具的问题，是我自己逻辑写得粗糙。

**坑三：以为免费额度很少。** 5000次听起来不多，但如果你只监控一个小区的列表页，每30分钟一次，一天48次，一个月才1440次。试用阶段完全够验证方案可行性。

## 常见问题

### ScraperAPI 能抓链家和贝壳的数据吗？

我自己实测是可以的。开启 JavaScript 渲染后，链家的房源列表页和详情页都能正常返回完整数据。贝壳的结构类似，也没问题。不过各平台反爬策略会更新，偶尔需要调整请求参数。

### 不会写代码能用吗？

有一定门槛。你至少需要会写简单的 Python 或 Node.js 脚本来调用 API 和解析数据。但 ScraperAPI 的文档写得很清楚，照着示例改目标 URL 就行。如果完全零基础，可能需要先花一两天学下基础。

### 跟八爪鱼、后羿采集器这类可视化工具比怎么样？

定位不同。可视化工具上手快但灵活性差，碰到复杂反爬就歇菜。ScraperAPI 是底层能力，你可以在上面搭任何自定义逻辑——定时触发、条件过滤、多平台聚合、自动通知，这些可视化工具很难做到。

### 一个月大概花多少钱？

看你的监控规模。个人盯一两个小区，免费档或 Hobby 档就够。如果是小团队做数据服务，Startup 或 Business 更合适。我个人每月花费折合人民币两百多，比之前买代理IP的开销还低。

### 数据抓下来怎么做监控通知？

ScraperAPI 只负责把网页内容拿回来，通知逻辑需要你自己写。我用的是 Python 脚本 + Server酱推送到微信，也有人用企业微信机器人或者钉钉 Webhook。技术上都很简单，几行代码的事。
